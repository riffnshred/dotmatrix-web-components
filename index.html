Getting started

Dotmatrix is a set of web components for the control pages of LED matrix projects. The whole page is one grid of dots, like the panels it controls, and every component draws on that grid. It is one script with no dependencies: no build step, no CDN and no web fonts, so a Raspberry Pi or an ESP32 can serve it offline.

Put dotmatrix.js next to your page, load it in the <head>, and put everything inside <dot-app>:

These attributes work the same way on every component that has them:

Words inside <em>, <b>, <strong> or <mark> are drawn in the accent colour. Accented letters (é, ç, ü…) are drawn too, and a character the fonts lack shows as a box.

App

<dot-app> The page. Put it straight inside <body> and everything else inside it. It applies the dark theme, shows the unlit grid, and centres each child in a column. A <dot-bar> as its first child spans the page and sits flush with the top.

Bar

<dot-bar> The top bar: a title, room for an icon or actions on each side, and a rule below. Inside <dot-app> it spans the page and clears the notch. It scrolls with the page.

Panel

<dot-panel> A card: a one-dot frame with its title set into the top edge. Its children stack with a gap between them.

JS: the open property, and a toggle event when a collapsible panel opens or closes.

Grid

<dot-grid> Layout only; it draws nothing. Children go in as many columns as fit, or in a wrapping row with row. Gaps are whole dots.

Rule

<dot-rule> A one-dot divider across the width it has.

Matrix

<dot-matrix> A dot surface for part of a page: a black area showing the unlit grid, which the components inside it line up with. Use it to put dots on a page that is not a <dot-app>. It has no attributes; size and pad it with CSS.

Heading

<dot-heading> A heading in the 5×7 capitals. It wraps between words, and steps down a size rather than break a word.

Text

<dot-text> Body text in the mixed-case 5×9 font, wrapped to its width. For paragraphs, labels and notes.

Value

<dot-value> A readout: a label, a large value, its unit and a note. The value steps down a size rather than overflow.

JS: el.value = 24.1 updates it.

Icon

<dot-icon> One 7×7 icon. With a label it is an image with that name; without one, screen readers skip it.

Marquee

<dot-marquee> Text scrolling right to left through a frame, one dot per step, like a message on the panel. With reduced motion it stands still and wraps.

JS: the speed, paused and pauseOnHover properties.

Button

<dot-button> A pill-shaped button. With type="submit" or "reset" it acts on its form, and Enter in one of the form's fields submits it, as with a native button. It adds no name or value to the form data.

JS: the disabled and loading properties; listen for click.

Slider

<dot-slider> A range input: its label and value on one line, a rail below. Drag it, or focus it and use the arrow keys. It works in forms and with htmx like a native range.

JS: the value property; an input event while it moves and change when it is let go.

Toggle

<dot-toggle> An on/off switch with its label. The whole row is the switch. In a form it acts like a checkbox: it sends its value only while on.

JS: the checked property; input and change events on every switch.

Input

<dot-input> A text field drawn in dots around a native <input>. The input does the real work (typing, autofill, validation, form data), so name, type, value, placeholder, required and hx-* go on the input.

JS: setting input.value from a script does not repaint the dots. Set dotInput.value instead, or call dotInput.render().

Status

<dot-status> A connection state as a coloured light and a word. Screen readers announce it when it changes.

JS: el.state = 'error' changes it.

LED

<dot-led> An indicator light, with text beside it if you give it some.

Badge

<dot-badge> A short tag on a dim pill.

Forms and htmx

Sliders and toggles are form controls, and <dot-input> wraps a real input, so a plain <form> posts them all and FormData reads them. Try it: Apply shows what the form would send.

htmx sends them like native inputs. To send each change as it happens:

  • Give sliders and toggles hx-trigger="change". Without it, htmx waits for a click.
  • An unchecked toggle sends nothing, like a checkbox.
  • On <dot-input>, name and hx-* go on the inner <input>.
  • To post a whole form, put hx-post on the <form> and use a type="submit" button.

Theming

Dark only. <dot-app> applies the palette below, and any style of your own overrides it: set the properties on :root. Colours are painted into the dots, so a change made from a script shows after Dotmatrix.refresh().

JavaScript

The script adds one global, Dotmatrix.

The NHL logos example paints its own canvas this way, lined up with the page grid through Dotmatrix.pitch.

Example pages

Whole pages built on the kit, in the examples/ folder. Each one loads ../dotmatrix.js.

  • Components: every component on one page. With #check, the unlit grid is brighter, so a dot off the grid shows up, and characters the fonts lack are red.
  • Sign-in: a device sign-in page, a plain form posting to /login. A script fakes the server: sign in as admin with the password matrix.
  • NHL logos: an experiment, the 32 NHL logos at panel resolution, painted on the page grid.
